# Налаштування SD Maid SE
{: #setting-up-sd-maid-se }
Інформація про різні кроки налаштування SD Maid SE.

SD Maid пристосовується до наявного доступу. Хоча всі дозволи необов'язкові, якщо не надати жодного дозволу, більшість функцій не працюватиме. SD Maid працює найкраще, коли виконано всі пункти налаштування.

SD Maid автоматично спробує виконати деякі кроки налаштування, якщо доступний [root](#root-access) або [доступ ADB](#shizuku).

Деякі дозволи перетинаються або є надмножинами одне одного, наприклад, ви можете надати SD Maid і root-доступ, і доступ ADB. SD Maid завжди намагається використати найкращий можливий спосіб доступу для будь-якої дії, а якщо це не вдається, повторює спробу з другим за якістю способом, потім із третім тощо. Надання SD Maid дозволів, що перетинаються, підвищує надійність.

> **Порада:** деякі кроки налаштування нижче передбачають виконання команд ADB. Якщо на вашому комп'ютері не налаштовано ADB, ви можете скористатися [Web ADB Helper](https://d4rken.github.io/web-adb/), щоб виконати їх прямо з браузера.

## Керування сховищем
{: #manage-storage }

Дозвіл «Керування сховищем» є дозволом на широкий доступ до сховища.

* На Android 12 і старіших він надає доступ до всього загальнодоступного сховища.
* На Android 13+ він так само надає доступ до всього загальнодоступного сховища, але не до підпапок у `Android/data`.

## Статистика використання
{: #usage-statistics }

Дозволи статистики використання дають SD Maid доступ до розмірів даних і кешу, а також до відомостей про те, чи працює додаток і коли його востаннє використовували.

## Система доступу до сховища
{: #storage-access-framework }
SD Maid використовує [Android Storage Access Framework (SAF)](http://developer.android.com/guide/topics/providers/document-provider.html), щоб отримати доступ до додаткових областей сховища. SD Maid попросить вас надати доступ до певних шляхів, які недоступні лише з дозволом «Керування сховищем» (Just Android Things™️).

* Натисніть кнопку `Надати доступ` 
* Відкриється нове вікно
* Якщо правильний шлях уже вибрано, добре; інакше перейдіть до шляху, який потрібен SD Maid.
* Потім натисніть кнопку `Use this folder` («Використовувати цю папку»), пункт налаштування для цього шляху розблокується та стане зеленим.

Повторюйте цей процес, доки всі шляхи не стануть зеленими.

### SAF: усунення проблем
{: #saf-troubleshooting }
На випадок, коли щось іде не за планом.

#### SAF: доступ до `Android/data|obb`
{: #saf-androiddataobb-access }

На Android 11 та Android 12 надати доступ до `Android/data|obb` неможливо з новішими версіями системного додатка `Files` (`com.google.android.documentsui`). Якщо встановлений додаток `Files` орієнтований на Android 14 (рівень API 34) або новіший, SD Maid приховує запит доступу SAF для цих шляхів (як на Android 13+).

Google Play оновлює додаток `Files` через службу `Google Play system update`. Оригінальний додаток «Files» (зібраний для рівня API 31, наприклад `aml_doc_310851020 (310851020)`), що постачався з ОС Android 12, дозволяє SD Maid відкрити вікно вибору шляху SAF для `Android/Data`, тоді як найновіший додаток «Files» (зібраний для рівня API 34 або новішого, наприклад `14-10492947 (340916000)`) цьому перешкоджає.

**Обхідний шлях:**

Можна видалити оновлення додатка `Files`, а потім налаштувати SD Maid. Повторне оновлення додатка `Files` не скасує вже надані дозволи.

* Відкрийте налаштування пристрою
* Перейдіть до «Apps & notifications» (Додатки та сповіщення) або «Application Manager» (Диспетчер додатків)
* Знайдіть системний додаток `Files`
* Торкніться меню з трьома крапками, зазвичай у правому верхньому куті
* Виберіть «Uninstall updates» (Видалити оновлення)

або

_Цю команду також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

`adb uninstall com.google.android.documentsui`

#### SAF: OPEN_DOCUMENT_TREE ActivityNotFoundException
{: #saf-open_document_tree-activitynotfoundexception }

Надання доступу до шляхів через Storage Access Framework потребує додатка, який дає користувачеві змогу підтвердити шляхи, до яких буде надано доступ. Цей додаток називається «Documents» («Документи»). Це системний додаток, вбудований у кожен пристрій Android починаючи з Android 5.0  (`com.android.documentsui` або `com.google.android.documentsui`). Якщо ви отримуєте цю помилку, хтось видалив або вимкнув цей додаток. Найчастіше хтось запустив надто завзятий інструмент для «очищення від bloatware», який його вимкнув. Його можна знову ввімкнути через ADB:

_Ці команди також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

```
adb shell pm enable com.android.documentsui
or
adb shell pm enable com.google.android.documentsui
```

#### SAF: порожнє вікно
{: #saf-empty-window }
Якщо вікно для надання доступу до шляхів порожнє, то, можливо, вимкнено пакет постачальника зовнішнього сховища (`com.android.externalstorage`) (імовірно, надто завзятим інструментом для «очищення від bloatware»). Його можна знову ввімкнути через ADB:

_Цю команду також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

```
adb shell pm enable com.android.externalstorage
```

Повторний запуск `Google Play system update` відновить оновлення. Також можна вручну завантажити оновлену версію з [APKMirror.com](https://www.apkmirror.com/apk/google-inc/files-6/).

## Сповіщення
{: #notifications }

Без цього дозволу SD Maid не зможе показувати сповіщення. На деяких ROM це може погіршити надійність роботи у фоні.

## Інвентар додатку
{: #app-inventory }

SD Maid потребує дозволу `QUERY_ALL_PACKAGES`, щоб перевіряти, які додатки встановлено на вашому пристрої (тобто [«видимість переліку встановлених додатків»](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en)). Див. також [«Дозвіл статистики використання»](/uk/setup#usage-statistics)

Дозвіл `QUERY_ALL_PACKAGES` обов'язковий для:

* [Пошуку рештків (CorpseFinder)](/uk/corpsefinder): щоб зрозуміти, які файли можна видалити, SD Maid має знати, чи встановлено у вас додатки, яким вони можуть бути потрібні.
* [Очищувача додатків (AppCleaner)](/uk/appcleaner): визначення кешів для кожного додатка
* [Управління додатками (AppControl)](/uk/appcontrol): можливість показати всі встановлені додатки
* [Аналізатора сховища (StorageAnalyzer)](/uk/storageanalyzer): віднесення зайнятого місця до встановлених додатків

Цей дозвіл існує починаючи з [Android 11](https://developer.android.com/training/package-visibility) і зазвичай надається за замовчуванням. Починаючи з Android 14 існують пристрої (наприклад, [#1015](https://github.com/d4rken-org/sdmaid-se/issues/1015), [#1354](https://github.com/d4rken-org/sdmaid-se/issues/1354)), на яких цей дозвіл не надається за замовчуванням або може бути відкликаний.

### Недійсний список додатків
{: #invalid-app-list }

На деяких пристроях дозвіл «App list» («Список додатків», `QUERY_ALL_PACKAGES` / `GET_INSTALLED_APPS`) надано, але система все одно повертає **неповний список встановлених додатків**, наприклад список, у якому бракує основних системних пакетів, як-от `android`. Коли SD Maid це виявляє, він показує в картці налаштування попередження **«Недійсний перелік додатків»** і примітку **«Можливе обмеження пристрою»** замість того, щоб продовжувати.

SD Maid зупиняється тут навмисно: якщо він не бачить повного списку встановлених додатків, він не може надійно визначити, які файли належать додатку, що досі встановлений. Продовження попри це могло б означати видалення даних, які належать додатку, якого SD Maid просто не побачив, тому функції, пов'язані з додатками, залишаються вимкненими, доки не буде доступний повний список.

**Що можна спробувати:**

* Відкрийте системні налаштування та переконайтеся, що SD Maid має дозвіл «App list» («Список додатків»). У деяких виробників цей перемикач має іншу назву (наприклад, «Query all packages», тобто «Запитувати всі пакети») або розташований на окремому екрані «Privacy» («Конфіденційність») чи «Permission manager» («Менеджер дозволів»).
* Перевірте, чи не фільтрує список додатків, які бачить SD Maid, вбудований засіб економії батареї, захист конфіденційності або функція «приховування додатків», і виключіть із неї SD Maid.
* Перезавантажте пристрій і знову відкрийте SD Maid, щоб стан дозволу було перевірено заново.

Якщо дозвіл «App list» («Список додатків») уже надано, а список і далі вважається недійсним, зазвичай це **обмеження пристрою**, а не те, що можна виправити: деякі системи (наприклад, HarmonyOS або сильно змінені збірки Android) ніколи не передають стороннім додаткам повний список додатків. Приклад див. у [#2441](https://github.com/d4rken-org/sdmaid-se/issues/2441).

У такому разі інструменти, пов'язані з додатками ([Пошук рештків](/uk/corpsefinder), [Очищувач додатків](/uk/appcleaner), [Управління додатками](/uk/appcontrol)), залишаються вимкненими для захисту ваших даних, але [Аналізатор сховища](/uk/storageanalyzer) і далі працює: він показує, скільки місця зайнято у вашому сховищі, лише з меншою деталізацією, бо розміри папок показуються лише для перегляду і не можуть бути віднесені до окремих додатків.

## Сервіс спеціальних можливостей
{: #accessibility-service }
Сервіс спеціальних можливостей дає SD Maid змогу взаємодіяти з вашим пристроєм як людина, тобто бачити екран і натискати кнопки. SD Maid може використовувати його для автоматизації монотонних дій, як-от натискання «Очистити кеш» у сотнях додатків. Сервіс спеціальних можливостей є службою, яку сам додаток запустити не може: її має запустити система, оскільки такий тип служби надає додатку додатковий доступ до вашого пристрою.

### ACS: усунення проблем
{: #acs-troubleshooting }

Служба може перестати працювати й вимагати повторного ввімкнення за різних обставин:
* Ви оновлюєте додаток.
* Додаток аварійно завершує роботу. Якщо це стається, повідомте про це як про помилку. Якщо це стається надто часто, можливо, ви не зможете перезапустити службу вимкненням і ввімкненням, доки не перезавантажите пристрій.
* Система зупиняє додаток через надто агресивну «оптимізацію батареї» (див. також <https://dontkillmyapp.com/>)
* Власний додаток безпеки виробника вимикає її (див. [Заблоковано Phone Manager](#acs-blocked-by-phone-manager-oneplus-oppo-realme))

#### ACS: служба вимкнена
{: #acs-service-is-disabled }

Деякі ROM (наприклад, MIUI) відомі тим, що агресивно зупиняють усе, що не внесено до білого списку виробником пристрою.
Якщо вас постійно просять знову ввімкнути сервіс спеціальних можливостей, можливо, система вимикає його щоразу, коли SD Maid не використовується активно.

Спробуйте вимкнути оптимізацію батареї, а на ROM MIUI є додатковий параметр «Autostart» (автозапуск), увімкніть його для SD Maid. Для пристроїв Xiaomi/POCO/Redmi:

* Перейдіть до `Security>Manage applications>Auto start in background` і дозвольте це для SD Maid.
* Перейдіть до `Security>Increase speed>Lock apps` і виберіть SD Maid.


Також можна надати додатковий дозвіл, який [дає SD Maid змогу автоматично перезапускати службу](#acs-automatic-service-restart).

[<img src="/assets/images/setup/acs-disabled.webp" width="100">](/assets/images/setup/acs-disabled.webp)

#### ACS: заблоковано Phone Manager (OnePlus, OPPO, Realme)
{: #acs-blocked-by-phone-manager-oneplus-oppo-realme }

В OxygenOS і ColorOS попередньо встановлений додаток «Phone Manager» може самостійно вимикати сервіс спеціальних можливостей, зазвичай протягом секунди після завершення очищення. Після цього перемикач спеціальних можливостей Android справді вимкнений, тож здається, що SD Maid перестав працювати посеред виконання.

Вимкніть цю функцію в `Phone Manager>Utilities>Block suspicious app activities`.

На тому самому екрані зберігається список того, що було заблоковано. Записи з позначкою «Abnormal device control» («Аномальне керування пристроєм») із часом, що збігається з очищеннями, які ви запускали, підтверджують, що причина саме в цьому. Перемикач «Blocking alerts» («Сповіщення про блокування») поруч лише визначає, чи отримуєте ви сповіщення, тож коли сповіщення вимкнено, це відбувається непомітно.

#### ACS: увімкнення через ADB
{: #acs-enable-via-adb }

Якщо на вашому пристрої немає способу ввімкнути сервіси спеціальних можливостей через екран (наприклад, на телевізорі), службу можна ввімкнути через ADB, виконавши:

_Цю команду також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

```bash
adb shell settings put secure enabled_accessibility_services eu.darken.sdmse/.automation.core.AutomationService
```

#### ACS: автоматичний перезапуск служби
{: #acs-automatic-service-restart }

_Примітка: це просунутий прийом, призначений для досвідчених користувачів._

Можна надати додатковий дозвіл, який дає SD Maid змогу самостійно перезапускати службу.
Дозвіл називається `WRITE_SECURE_SETTINGS` і може бути наданий лише [через ADB](https://www.google.com/search?q=android+adb).
Якщо ADB у вас налаштовано, виконайте цю команду, щоб надати дозвіл:

_Цю команду також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

```bash
adb shell pm grant eu.darken.sdmse android.permission.WRITE_SECURE_SETTINGS
```

Коли цей дозвіл надано, SD Maid може за потреби вмикати службу за допомогою команди, [описаної тут](#acs-enable-via-adb).
SD Maid використовуватиме це, лише якщо ви хоча б один раз увімкнули сервіс спеціальних можливостей вручну.
Якщо ви знову зайдете в налаштування й скажете SD Maid не використовувати сервіс спеціальних можливостей, цей прийом автоматичного перезапуску не використовуватиметься, доки ви знову не ввімкнете сервіс спеціальних можливостей вручну.

Щоб знову забрати цей дозвіл у SD Maid, скористайтеся цією командою:

_Цю команду також можна виконати за допомогою [Web ADB Helper](https://d4rken.github.io/web-adb/)._

```bash
adb shell pm revoke eu.darken.sdmse android.permission.WRITE_SECURE_SETTINGS
```

Якщо ви отримуєте `Operation not allowed: java.lang.SecurityException`, [див. тут](https://stackoverflow.com/questions/52079343). Деякі пристрої обмежують дозволи ADB. Перевірте, чи є в параметрах розробника додатковий параметр (наприклад, `Disable Permission Monitoring`), який потрібно перемкнути; після виконання команди його можна знову вимкнути.

#### ACS: Advanced Protection
{: #acs-advanced-protection }

На Android 17 і новіших режим Google [**Advanced Protection**](https://developer.android.com/privacy-and-security/advanced-protection-mode) (розширений захист) не дає додаткам, які не є спеціалізованими засобами спеціальних можливостей (програми зчитування з екрана, доступ за допомогою перемикачів тощо), використовувати сервіс спеціальних можливостей. SD Maid є інструментом для обслуговування та очищення, тому, поки ввімкнено Advanced Protection, його сервіс спеціальних можливостей **неможливо** ввімкнути: Android відхиляє службу на системному рівні, навіть якщо ви намагаєтеся надати її через root або доступ ADB.

SD Maid не може зробити для себе виняток: право на це мають лише додатки, які Google класифікує як засоби спеціальних можливостей, а засоби очищення явно виключено.

У вас є два варіанти:

- **Використовуйте root або доступ ADB** Коли налаштовано root або доступ ADB, Очищувач додатків (AppCleaner) у SD Maid очищує кеші додатків прямим системним викликом і **не** потребує сервісу спеціальних можливостей. Із **root** це також охоплює очищення окремих вибраних додатків. З **доступом ADB** повне очищення «всіх додатків» працює без сервісу спеціальних можливостей, але очищення кешу *конкретних* вибраних додатків усе одно залежить від нього. Налаштуйте це в розділі «Налаштування» SD Maid → [Root доступ](#root-access) або [Доступ ADB](#shizuku).
- **Вимкніть Advanced Protection**, якщо вам потрібне саме очищення через спеціальні можливості. Він знаходиться в `Settings → Security & privacy → Advanced Protection` (точний шлях залежить від пристрою). Якщо згодом знову його ввімкнути, сервіс спеціальних можливостей буде знову вимкнено.

#### ACS: обмеження AppOps
{: #acs-appops-restrictions }

Android 13+ може застосовувати додаткові обмеження до додатків, встановлених в обхід магазинів (side-loading). Тож якщо SD Maid встановлено не з відомого (для Google) джерела, як-от Google Play чи інші магазини додатків, ви, можливо, не зможете напряму надати SD Maid деякі дозволи, наприклад запустити сервіс спеціальних можливостей.

##### OxygenOS 15 - OnePlus
{: #oxygenos-15---oneplus }

OnePlus забули (або просто не захотіли) додати дію `Allow restricted settings` («Дозволити обмежені налаштування») до налаштувань додатків в OxygenOS 15. Якщо ви встановлюєте не через Google Play, інсталятор має встановити прапорець `INSTALL_ALL_WHITELIST_RESTRICTED_PERMISSIONS`. Якщо у вас налаштовано Shizuku, можна скористатися [додатком «Install with Options»](https://github.com/zacharee/InstallWithOptions).


##### Інші ROM
{: #other-roms }

Щоб зняти ці обмеження, відкрийте в системі екран налаштувань додатка SD Maid. Відкрийте меню у правому верхньому куті та виберіть `Allow restricted settings` («Дозволити обмежені налаштування»), після чого можна повернутися до списку сервісів спеціальних можливостей і ввімкнути службу SD Maid.

**Примітка:**
Щоб покращити зручність використання (це сарказм), Google вирішив, що цей параметр буде видимим, лише якщо:

* Ви хоча б раз побачили повідомлення «Restricted setting» («Обмежене налаштування») після натискання на запис сервісу спеціальних можливостей SD Maid
* Ви відкрили системні налаштування та перейшли на сторінку налаштувань SD Maid вручну, а не через інший додаток чи ярлики.

## Root доступ
{: #root-access }

З root-доступом SD Maid має повний доступ до вашого пристрою і може виконувати найретельніше можливе сканування. Зазвичай це означає, що ви розблокували завантажувач і встановили Magisk.

Якщо SD Maid вважає, що на вашому пристрої може бути root, він спершу попросить root-доступ. Якщо root-доступ надано, SD Maid використає його, щоб надати якомога більше інших дозволів. Root-доступ є найвищим рівнем доступу, який можна дати додатку; інші дозволи тоді потрібні лише для зручності та продуктивності, тому вони не потребують окремої згоди під час налаштування, якщо SD Maid уже має root.

## Доступ ADB
{: #shizuku }

Доступ ADB дає SD Maid змогу використовувати інтерфейс налагодження Android (ADB) для операцій із підвищеними правами. Для цього потрібен окремий додаток, який запускає службу ADB на вашому пристрої та надає іншим додаткам доступ до неї: [Porter](#porter) або [Shizuku](#using-shizuku). Це модифікація, яку ви можете внести у свій телефон і якою можуть користуватися інші додатки.

Вона схожа на root, але це не одне й те саме. Дозволи трохи слабші, зате модифікація не є постійною і не потребує розблокування завантажувача.

### Porter
{: #porter }

[Porter](https://porter.darken.eu) є моїм підтримуваним форком Shizuku з необов'язковою підтримкою root. На його вебсайті пояснено, як його встановити й запустити. На Android 11 і новіших бездротове налагодження дає змогу запустити його без комп'ютера.

Якщо ви налаштовуєте доступ ADB вперше, використовуйте Porter. Збірки SD Maid із GitHub і F-Droid направляють вас до Porter, коли не встановлено жодного додатка для доступу ADB. Збірка з Google Play направляє вас до Shizuku в Google Play, але з Porter працює так само.

Якщо встановлено і Porter, і Shizuku, SD Maid використовує Porter. Тоді картка налаштування показує `Porter встановлено, тому SD Maid чекає на Porter замість Shizuku`. Запустіть Porter, щоб продовжити, або видаліть його, якщо хочете, щоб SD Maid використовував Shizuku.

### Використання Shizuku
{: #using-shizuku }

Існує дві збірки Shizuku:

* [Форк від thedjchi](https://github.com/thedjchi/Shizuku) ([посібник із налаштування](https://github.com/thedjchi/Shizuku/wiki/setup)) активно підтримується, і, за повідомленнями, працює на пристроях, де оригінал [ніколи не підключається](#shizuku-never-connects).
* [Оригінал від RikkaApps](https://shizuku.rikka.app/guide/setup/) і далі добре працює на більшості пристроїв.

Їх не можна встановити одночасно. Якщо оригінал у вас уже працює, переходити немає потреби.

### Надання доступу
{: #granting-access }

Після того як ви налаштували Porter або Shizuku:

* У налаштуванні SD Maid виберіть `Спробуй використовувати доступ ADB`. Це внутрішній параметр SD Maid, ним можна вмикати й вимикати використання доступу ADB у SD Maid
* Після надання згоди діалог від Porter або Shizuku запитає, чи може SD Maid його використовувати
* Підтвердьте діалог
* Картка налаштування `Доступ ADB` показує, чи може SD Maid підключитися

Налаштування доступу ADB, якщо ви вже надали SD Maid root-доступ, не вмикає додаткових функцій, але підвищує надійність. Якщо дії з правами root не вдаються, SD Maid повторить спробу з доступом ADB.

### Доступ ADB: усунення проблем
{: #shizuku-troubleshooting }

Перевірити стан доступу ADB у SD Maid можна в `Налаштування > Налаштування`, переглянувши картку налаштування `Доступ ADB`. На ній має бути напис `SD Maid тепер може використовувати доступ ADB через Porter` (або `через Shizuku`).

* `Porter ще не дозволило SD Maid`: підтвердьте діалог доступу або дозвольте SD Maid у додатку Porter (чи Shizuku).
* `Porter заперечує доступ SD Maid`: SD Maid отримав остаточну відмову. Відкрийте Porter (або Shizuku) і дозвольте SD Maid там.
* `Оновити Porter, щоб використовувати його з SD Maid` або `Ця версія SD Maid занадто стара для Porter`: ці два додатки не мають сумісних версій. Оновіть той, який названо на картці.

#### Shizuku ніколи не підключається
{: #shizuku-never-connects }

Картка показує `Помилка доступу ADB` і `Shizuku працює, але воно ніколи не з'єднало SD Maid зі своїм допоміжним сервісом.` Старіші версії показували `Waiting for link with Shizuku` («Очікування зв'язку з Shizuku») або `Shizuku link failed` («Помилка зв'язку з Shizuku»).

Відкрийте додаток Shizuku. Якщо він каже, що працює, і SD Maid є в його списку авторизованих, Shizuku налаштовано правильно, і повторне налаштування не допоможе. Збій відбувається в допоміжній службі Shizuku: вона аварійно завершується під час запуску, перш ніж встигає відзвітувати, і SD Maid здається приблизно через 15 секунд. `Повторити` виконує ту саму перевірку й так само зазнає невдачі.

Це помилка Shizuku ([RikkaApps/Shizuku#1198](https://github.com/RikkaApps/Shizuku/issues/1198)), а не SD Maid, і вона ламає будь-який додаток, що використовує допоміжну службу Shizuku. Вона стосується пристроїв MediaTek, а також пристроїв із HyperOS або MIUI.

За повідомленнями, [форк від thedjchi](https://github.com/thedjchi/Shizuku) це виправляє. Щоб перейти:

* Спершу видаліть оригінал, вони не можуть існувати одночасно
* Скасуйте його сполучення в бездротовому налагодженні, якщо ви ним користувалися
* Встановіть форк із його [випусків](https://github.com/thedjchi/Shizuku/releases) і дотримуйтеся його [посібника з налаштування](https://github.com/thedjchi/Shizuku/wiki/setup)
* Знову надайте дозвіл Shizuku для SD Maid і всього іншого, що ним користувалося
